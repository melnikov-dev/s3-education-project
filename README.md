# S3 — краткий конспект

## Что такое S3

**S3 (Simple Storage Service)** — облачное объектное хранилище. Приложение работает с ним через API, а AWS (или другой хостер) берёт на себя инфраструктуру хранения, масштабирование и обеспечение высокой долговечности данных.

S3 появился в 2006 году. Он не изобрёл хранение файлов, а сделал масштабируемое объектное хранилище доступным как управляемый сервис.

## Основные понятия

- **Bucket** — контейнер для объектов.
- **Object** — данные (например, файл) и метаданные.
- **Key** — имя объекта внутри bucket, например `users/42/avatar.jpg`.

В классическом S3 ключ — не физический путь к файлу. Слеши в ключе обычно используются для визуальной группировки, а не обозначают настоящие каталоги.

Приложение обращается к объектам через API: загрузка (`PUT`), чтение (`GET`), удаление (`DELETE`) и получение метаданных (`HEAD`). Для получения объекта нужны имя bucket и key. Для конкретной версии также указывается `VersionId`.

## Зачем использовать S3

- Хранить пользовательские файлы, изображения, видео и документы.
- Хранить резервные копии, архивы и логи.
- Не управлять собственными дисками и файловым сервером.
- Масштабировать хранилище без самостоятельного обслуживания инфраструктуры.

Типичный подход: **файлы хранить в S3, а в базе данных — их key и связанные метаданные**.

## Классы хранения (Storage Classes)

Класс хранения влияет на стоимость, доступность и скорость получения данных.

- **S3 Standard** — часто используемые файлы; хороший вариант по умолчанию.
- **S3 Intelligent-Tiering** — если частота доступа непредсказуема; автоматически перемещает объекты между подходящими уровнями доступа.
- **S3 Standard-IA** — редко читаемые данные, к которым нужен быстрый доступ.
- **S3 Glacier Instant Retrieval** — архивные данные, которые иногда нужно получить немедленно.
- **S3 Glacier Flexible Retrieval** — архивы, восстановление которых может занимать минуты или часы.
- **S3 Glacier Deep Archive** — долгосрочные архивы, к которым обращаются крайне редко.

Более дешёвое хранение может включать дополнительные расходы на запросы, извлечение данных, переходы между классами и минимальный срок хранения.

## Контроль доступа (Access Control)

Основные механизмы:

- **IAM Policies** — определяют, какие действия разрешены пользователю или роли AWS.
- **Bucket Policy** — задаёт правила доступа к bucket и объектам в нём.
- **S3 Block Public Access** — блокирует настройки, способные открыть данные публично.
- **Pre-signed URL** — временная подписанная ссылка для выполнения конкретной операции с объектом.
- **ACL** — механизм списков контроля доступа; в новых проектах обычно не нужен без специальной причины.

Практические правила:

1. По умолчанию держать bucket приватным и включать Block Public Access.
2. Выдавать приложению только необходимые IAM-разрешения.
3. Для приватных файлов backend сначала проверяет права пользователя, а затем при необходимости выдаёт короткоживущую pre-signed URL.
4. Не считать key секретом: знание ключа не должно заменять проверку доступа.
5. Права AWS и права пользователей самого приложения — разные уровни. Приложение самостоятельно проверяет, имеет ли пользователь право на конкретный файл.

## Шифрование (Encryption)

Шифрование защищает данные, но не заменяет контроль доступа.

- **In transit** — HTTPS/TLS защищает данные при передаче.
- **At rest** — шифрование защищает данные во время хранения.

Основные варианты серверного шифрования:

- **SSE-S3** — ключами управляет S3; обычно достаточно для стандартного приложения.
- **SSE-KMS** — используется AWS KMS; даёт больше возможностей для управления ключами и аудита.
- **SSE-C** — клиент передаёт собственный ключ при соответствующих запросах.

**Client-side encryption** — приложение шифрует файл до отправки в S3. Это отдельный подход, который требует самостоятельно продумать хранение и управление ключами.

Новые объекты в S3 по умолчанию шифруются при хранении с помощью SSE-S3. Для доступа к объекту всё равно нужны соответствующие разрешения.

## Версионирование (Versioning)

Версионирование позволяет сохранять несколько версий объекта под одним key.

- Повторная загрузка объекта с тем же key создаёт новую версию.
- Старую версию можно запросить по `VersionId`.
- Обычное удаление при включённом версионировании обычно создаёт **delete marker** — маркер удаления, а предыдущие версии остаются.
- Старые версии занимают место и тарифицируются.
- Версионирование нужно включить для bucket.

Версионирование помогает восстановить случайно перезаписанный или удалённый файл, но не заменяет резервное копирование. Для дополнительной защиты можно ограничивать права на удаление и использовать S3 Object Lock.

## Практические настройки для небольшого проекта

- **Хранение:** `S3 Standard`.
- **Доступ:** приватный bucket, IAM с минимально необходимыми разрешениями и Block Public Access.
- **Загрузка/скачивание приватных файлов:** backend проверяет права и выдаёт pre-signed URL, чтобы клиент мог обращаться к S3 напрямую.
- **Шифрование:** HTTPS/TLS и SSE-S3 как стандартная отправная точка.
- **Версионирование:** включать, если нужна возможность восстановления предыдущих версий.
- **Очистка:** при необходимости настроить Lifecycle Policy для старых версий и архивирования.

## Интеграция S3 в этом проекте

Проект — Express-сервер, который выступает посредником между HTTP-клиентом и S3-совместимым хранилищем Selectel. Для запросов к хранилищу используется `@aws-sdk/client-s3` (AWS SDK v3): несмотря на название пакета, клиент можно направить на совместимый с S3 endpoint другого провайдера.

При запуске `src/app.ts` создаёт `Server`, который подключает JSON-парсер Express и роутер с префиксом `/storage`. В `StorageService` создаётся один `S3Client` с endpoint, регионом и статическими ключами доступа из переменных окружения. Ключи остаются на сервере: браузер или другой HTTP-клиент с S3 напрямую в этой реализации не общается.

### Как проходит загрузка

1. `multer` разбирает `multipart/form-data` и принимает только одно поле `file`.
2. Используется `multer.memoryStorage()`: файл полностью собирается в `Buffer` в оперативной памяти процесса. Установлены лимиты: один файл и не более 100 MiB.
3. Сервис берёт расширение из `file.originalname`, генерирует ключ формата `uploads/<random UUID><extension>` и вызывает `PutObject`.
4. В S3 передаются буфер, MIME-тип клиента в `ContentType` и исходное имя в пользовательских метаданных `originalname`.

UUID не даёт файлам с одинаковым исходным именем перезаписать друг друга. Вместе с тем `PutObject` возвращает служебный ответ S3, а не созданный `key`; клиенту нужно сохранить ключ самостоятельно либо получить его через листинг. Для production API удобнее вернуть `key` явно в ответе контроллера.

Так как файл держится в памяти до отправки, фактическое потребление памяти зависит от размера и числа одновременных запросов. Ограничение в 100 MiB не делает такую схему потоковой. Для больших файлов стоит перейти на потоковую передачу или выдавать pre-signed URL для прямой загрузки в S3.

### Как проходит скачивание и удаление

Для скачивания контроллер проверяет, что `key` — непустая строка, выполняет `GetObject` и передаёт `Body` в HTTP-ответ через `pipeline`. Поэтому содержимое объекта не собирается в памяти сервера целиком. Заголовок `Content-Type` берётся из S3, а при его отсутствии используется `application/octet-stream`; `Content-Disposition` установлен в `inline` и использует `Metadata.originalname`, либо сам `key` как запасное имя.

`DELETE` также требует непустой строковый `key`. Удаление идемпотентно со стороны S3: для несуществующего ключа запрос обычно завершается успешным ответом, что соответствует комментарию в сервисе. При включённом versioning это будет создание delete marker, а не физическое удаление всех версий.

`GET /storage` выполняет один `ListObjectsV2Command` без `Prefix`, `ContinuationToken` и обработки пагинации. Поэтому он запрашивает весь bucket, но возвращает только первую страницу результата S3 (обычно до 1000 объектов); API не предназначен для полного каталога больших bucket без доработки пагинации.

### Ограничения безопасности текущей реализации

В маршрутах нет аутентификации и авторизации. Любой, кто может обратиться к серверу, может загрузить файл, увидеть список объектов, скачать объект по известному ключу и удалить его — в пределах прав серверных S3-учётных данных. Перед развёртыванием во внешней сети необходимо добавить проверку пользователя и прав на конкретный ключ, не логировать секреты и выдать IAM/S3-ключам минимально необходимые разрешения.

Сервер проксирует операции сам и не формирует pre-signed URL. Такой подход упрощает контроль на backend, но добавляет сетевую нагрузку на него; для клиентских загрузок и скачиваний больших приватных файлов обычно после проверки прав выдают короткоживущую подписанную ссылку.

## Главное

**S3 — это объектное хранилище, к которому приложение обращается через API.** Bucket задаёт контейнер, key идентифицирует объект, класс хранения влияет на экономику доступа, политики контролируют разрешения, шифрование защищает данные, а версионирование хранит историю объектов.
